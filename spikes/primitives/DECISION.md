# قرار الـprimitive (المرحلة 0)

**القرار:** React Aria (`react-aria-components` 1.22.1) هي طبقة السلوك L3، ومحطوطة ورا adapter. وBase UI (`@base-ui/react` 1.9.0) هي البديل لو React Aria فشلت في حاجة بعدين. Radix اتستبعدت.

**التاريخ:** 2026-11-05.
**الدليل:** `spikes/primitives/results.json`. اتولّد من `node scripts/spike-primitives.mjs` على Chrome 156 headless على Windows.

## السيناريو

نفس الصفحة اتبنت على المكتبات التلاتة (`spikes/primitives/main.tsx`)، وفيها حاجتين:
- **Dialog** جوّاه `CurrencyInput` بتاعنا، وده عنده عقد Escape خاص بيه.
- **Combobox** أسماء عملاء، والفلترة فيه بـ`matchText` بتاعنا (بحث بيتسامح مع الهمزات والتشكيل).

وده الاختبار الحقيقي اللي يهمنا: هل الـprimitive بيسيب طبقة العربي بتاعتنا تشتغل جوّاه من غير ما يكسرها؟

1. **Base UI:** التركيز بيقف لحظة على عنصر حماية (focus guard) برا الحوار، وبعدين بيتنقل لأول حقل في أقل من 50ms. اتسجّل كملاحظة مش كعيب، لأن المستخدم مش هيشوفه.
2. **Radix:** بيسمع للـEscape على الـdocument في مرحلة capture (`@radix-ui/react-use-escape-keydown`)، يعني قبل ما الحقل يشوف المفتاح أصلًا. فالحقل مايقدرش يمنع قفل الحوار، ومستخدم بيلغي تعديل في مبلغ هيخسر النموذج كله. الحل الوحيد إن الحوار يعرف حالة كل حقل جوّاه، وده كسر لعزل الطبقات.
3. **Radix:** مافيهوش Combobox. shadcn بيركّب واحد من Popover وcmdk، وده نمط تاني غير ARIA combobox.

## ليه React Aria وهي متعادلة مع Base UI في السلوك؟

الفرق في اللي العربي محتاجه بعد كده:

- **التقويم الهجري:** React Aria فيها DatePicker وCalendar وDateField، والتقاويم `islamic-umalqura` و`islamic-civil` و`islamic-tbla`. اتحقق منه هنا: 2026-11-05 ← «الخميس، ٢٥ جمادى الأولى ١٤٤٨ هـ». Base UI مافيهاش أي مكوّن تاريخ، يعني كنا هنبنيه من الصفر، وده من أصعب المكونات.
- **رسائل عربي جاهزة:** فيها رسائل مدمجة لـ19 مجموعة، منها combobox وcalendar وdatepicker وtable وtoast. **بس صيغ الجمع فيها مبسّطة:** بتستخدم one/other بس، والعربي فيه 6 صيغ (مثلًا «2 خيار» بدل «خياران»). عشان كده عقدنا ثابت: النصوص الداخلية بتيجي من طبقة المحتوى بتاعتنا عن طريق `labels`، ورسائل React Aria بديل احتياطي بس.
- **تحليل الأرقام والتواريخ حسب الـlocale** موجود لو احتجناه. بس حقل المبلغ هيفضل يستخدم L2 بتاعنا، لأن عقد الفاصلة الملتبسة عندنا مختلف.
- **التكلفة:** حوالي 8KB gzip زيادة عن Base UI في نفس الأجزاء.

## إزاي نحمي نفسنا من القرار ده (الـadapter)

- مكوّناتنا العامة مابتكشفش أي نوع من React Aria. الـprops على عقدنا (`onValueChange` و`open` و`disabled`)، مش `isDisabled` و`onSelectionChange`.
- الـadapter موجود في L3 بس، ومافيش ستايل بيقرا class من React Aria. الستايل بيقرا data-attributes بتاعتنا بس.
- نفس سكريبت التجربة بيفضل يشتغل كاختبار تكامل. لو حصل ترقية أو اتنقلنا لـBase UI، النتيجة بتتقارن على نفس الفحوصات.

## تعديل 2026-11-05: Dialog وDrawer يفضلوا بتوعنا

قبل ما ننقل الحوار على React Aria، ضفنا الحوار بتاعنا كمكتبة رابعة (`?lib=own`) على نفس الفحوص بالظبط. الفحوص بقت تختار العناصر بالـrole مش بالـtest id، عشان المقارنة تبقى عادلة.

**القاعدة من دلوقتي:** المكوّن ينتقل على الـadapter بس لما فحص يثبت إن فيه قدرة ناقصة عندنا. أمثلة على القدرات دي: التقاويم الهجرية، وcollections الـCombobox مع virtual focus، وبعد كده القوائم (menu) وتنقّل الجدول بالكيبورد. الفحوص دي بتفضل شغالة على الأربع مكتبات مع كل ترقية.
